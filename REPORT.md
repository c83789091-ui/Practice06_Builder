# Отчет по практической работе №6

## Тема

Реализация паттерна Builder на языке C#.

## Вариант

Вариант 1 - сборка компьютера.

По заданию компьютер может включать разные компоненты: процессор, оперативную память, видеокарту и жесткий диск. Каждая часть отличается в зависимости от конфигурации компьютера. Нужно реализовать интерфейс по принципу Builder и три конкретные реализации: `GamingPCBuilder`, `OfficePCBuilder`, `ServerPCBuilder`.

## Цель работы

Изучить паттерн проектирования Builder и реализовать программу, в которой сложный объект создается по шагам.

## Краткая теория

Builder, или "Строитель", - это порождающий паттерн проектирования. Он применяется тогда, когда объект состоит из нескольких частей и его удобнее создавать не сразу, а постепенно.

Главная идея паттерна: отделить процесс сборки объекта от конкретного результата. Один и тот же порядок действий может создавать разные варианты объекта.

В этой работе объектом является компьютер. Процесс сборки одинаковый:

1. Установить процессор.
2. Установить оперативную память.
3. Установить видеокарту.
4. Установить накопитель.
5. Получить готовый компьютер.

Но результат отличается, потому что игровой, офисный и серверный компьютеры имеют разные комплектующие.

## Ход решения задачи

### 1. Создание класса Computer

Сначала был создан класс `Computer`. Он описывает готовый компьютер и хранит его характеристики:

- `Processor` - процессор;
- `Ram` - оперативная память;
- `VideoCard` - видеокарта;
- `Storage` - жесткий диск или накопитель.

Также в классе переопределен метод `ToString()`. Он нужен для красивого вывода информации о компьютере в консоль.

### 2. Создание интерфейса IComputerBuilder

Далее был создан интерфейс `IComputerBuilder`. Он задает общий набор действий для любого строителя компьютера:

- `SetProcessor()` - установить процессор;
- `SetRam()` - установить оперативную память;
- `SetVideoCard()` - установить видеокарту;
- `SetStorage()` - установить накопитель;
- `GetComputer()` - вернуть готовый объект `Computer`.

Интерфейс не хранит конкретные детали. Он только задает правила, которым должны следовать все строители.

### 3. Создание GamingPCBuilder

Класс `GamingPCBuilder` реализует интерфейс `IComputerBuilder` и собирает игровой компьютер.

В игровой сборке используются:

- процессор `Intel Core i7`;
- оперативная память `32 GB DDR5`;
- видеокарта `NVIDIA GeForce RTX 4070`;
- накопитель `1 TB SSD`.

### 4. Создание OfficePCBuilder

Класс `OfficePCBuilder` также реализует интерфейс `IComputerBuilder`, но собирает офисный компьютер.

В офисной сборке используются:

- процессор `Intel Core i3`;
- оперативная память `8 GB DDR4`;
- встроенная графика `Integrated graphics`;
- накопитель `512 GB SSD`.

### 5. Создание ServerPCBuilder

Класс `ServerPCBuilder` собирает серверный компьютер.

В серверной сборке используются:

- процессор `AMD EPYC`;
- оперативная память `128 GB ECC`;
- видеокарта `Basic server adapter`;
- хранилище `4 TB RAID storage`.

### 6. Создание общего метода сборки

Для управления сборкой был создан метод `BuildComputer`.

Он принимает объект типа `IComputerBuilder`, вызывает одинаковые шаги сборки и возвращает готовый компьютер:

```csharp
builder.SetProcessor();
builder.SetRam();
builder.SetVideoCard();
builder.SetStorage();
return builder.GetComputer();
```

Этот метод выполняет роль "директора" в паттерне Builder. Он знает порядок сборки, но не знает, какие конкретно детали будут установлены. Детали выбирает конкретный строитель.

### 7. Вывод результата

В основной части программы создаются три компьютера:

```csharp
Computer gamingPc = BuildComputer(new GamingPCBuilder());
Computer officePc = BuildComputer(new OfficePCBuilder());
Computer serverPc = BuildComputer(new ServerPCBuilder());
```

После этого информация о каждом компьютере выводится в консоль.

## Ответы на контрольные вопросы

### 1. В чем суть паттерна Builder?

Суть паттерна Builder заключается в пошаговом создании сложного объекта. Паттерн отделяет процесс сборки объекта от его конкретного представления.

В данной программе процесс сборки компьютера одинаковый: установить процессор, оперативную память, видеокарту и накопитель. Но конкретные детали отличаются в зависимости от выбранного строителя.

### 2. Опишите базовую реализацию паттерна Builder на C#

Базовая реализация включает:

- класс продукта, например `Computer`;
- интерфейс строителя, например `IComputerBuilder`;
- конкретные строители, например `GamingPCBuilder`, `OfficePCBuilder`, `ServerPCBuilder`;
- управляющий метод или класс-директор, который вызывает шаги сборки;
- клиентский код, который выбирает нужного строителя и получает готовый объект.

### 3. Перечислите преимущества и недостатки паттерна Builder

Преимущества:

- удобно создавать сложные объекты;
- процесс создания объекта разбит на понятные шаги;
- можно создавать разные варианты объекта одним способом;
- легко добавить новый тип строителя;
- логика сборки отделена от самого объекта.

Недостатки:

- увеличивается количество кода;
- появляются дополнительные классы и интерфейсы;
- для простых объектов паттерн может быть избыточным;
- при изменении структуры объекта нужно обновлять всех строителей.
